# 06 — AI Agents

In module 04 the LLM answered a question. Here it gets to *act*.

An agent is given a goal and a set of tools, and it decides by itself which tool
to use, in what order, and when it is done. That is powerful, and it is also why
agents need guardrails — which is why human approval is in this module and not
somewhere at the end.

Start simple: one agent, one tool. Complexity comes later.

## 🎯 Learning Objectives

- Explain what an AI agent is and how it differs from a normal workflow
- Decide when a task needs an agent and when a plain workflow is the better answer
- Give an agent a tool and watch it choose to use it
- Write system instructions that keep an agent on task
- Add memory so the agent remembers earlier messages in a conversation
- Give an agent several tools without it getting confused
- Require a human to approve an action before the agent takes it

## 🧠 What You Will Learn

- **What is an AI agent?** — an LLM that runs in a loop with tools, until the goal
  is met
- **Agent vs workflow** — a workflow follows the path you drew; an agent chooses
  its own path. Predictable versus flexible, and why you usually want predictable
- **Tools** — the things an agent is allowed to do: search, fetch, calculate,
  write to a database
- **Tool calling** — how the model asks for a tool and receives the result back
- **Agent decision-making** — reading the agent's steps to see *why* it did what
  it did
- **Memory** — keeping the thread of a conversation across messages
- **System instructions** — the agent's job description, and why a vague one
  produces a vague agent
- **Multiple tools** — clear tool names and descriptions, so the agent picks right
- **Human approval** — pausing the agent and waiting for a person before anything
  is sent, paid, or deleted
