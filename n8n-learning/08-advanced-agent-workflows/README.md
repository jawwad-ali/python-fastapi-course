# 08 — Advanced Agent Workflows

One agent with a few tools has a limit. Past that point, the answer is not a
bigger prompt — it is better structure.

This module is about arranging agents and workflows so that each part has one
clear job, and so that a person stays in control of the decisions that matter.

## 🎯 Learning Objectives

- Break a large job into smaller agents and workflows that each do one thing
- Route incoming work to the right handler automatically
- Reuse logic across workflows instead of copying nodes
- Decide when one agent with many tools beats several specialised agents
- Insert a human approval step without the workflow losing its place
- Combine an agent with RAG, a database, and external APIs in one system

## 🧠 What You Will Learn

- **Agent orchestration** — one coordinator handing work to specialists
- **Routing** — classifying a request first, then sending it to the right path
- **Sub-workflows** — building a workflow once and calling it from many places
- **Multi-agent patterns** — and the honest trade-off: more agents means more
  places to go wrong, so use them only when one agent genuinely cannot cope
- **Human-in-the-loop** — the workflow pauses, a person decides, the workflow
  resumes
- **Approval workflows** — approve, reject, or edit before an action happens
- **Agent + RAG** — an agent that can look things up in your documents
- **Agent + database** — an agent that answers from live business data
- **Agent + external APIs** — an agent that acts on systems outside n8n
