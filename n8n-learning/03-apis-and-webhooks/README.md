# 03 — APIs and Webhooks

So far your workflows have worked with data that was already inside n8n. This
module connects them to the rest of the internet — both directions.

An **API** lets your workflow go and fetch something. A **webhook** lets something
outside come and start your workflow.

## 🎯 Learning Objectives

- Describe what happens when one program calls another over HTTP
- Call any REST API from n8n, even one with no ready-made node
- Choose correctly between a query parameter, a header, and a request body
- Authenticate to an API without ever typing a key into a node
- Receive data from an outside system using a webhook
- Send a reply back to whoever called your webhook

## 🧠 What You Will Learn

- **HTTP basics** — requests, responses, and what status codes like `200`, `401`
  and `500` are telling you
- **REST APIs** — the common pattern almost every web service follows
- **GET and POST** — fetching data versus sending data
- **Headers** — extra information sent with a request, such as who you are
- **Query parameters** — values added to the end of a URL
- **Request body** — the data you send with a POST
- **API authentication** — API keys, bearer tokens, and basic auth, stored as
  credentials rather than written into the workflow
- **The HTTP Request node** — the most useful node in n8n, because it can talk to
  anything
- **Webhooks** — giving your workflow its own URL so other systems can trigger it
- **Webhook responses** — replying immediately, or after the work is done
